## Basics

Shortcuts work while focus is anywhere inside the viewer; click the page or <kbd>Tab</kbd> to the document area first.

Shortcuts never fire while typing in an input, select or text area, or with <kbd>Alt</kbd>, <kbd>Ctrl</kbd> or <kbd>⌘</kbd> held, so browser and app shortcuts keep working. <kbd>Shift</kbd> with arrows is left alone for text selection.

### Toolbar and menu keys

The toolbar is a single tab stop. Inside it, <kbd>←</kbd> <kbd>→</kbd> <kbd>Home</kbd> <kbd>End</kbd> move between controls. On the **⋮ More actions** button, <kbd>Enter</kbd>, <kbd>Space</kbd> or <kbd>↓</kbd> open the menu on its first item and <kbd>↑</kbd> on its last; inside the menu, arrows move and <kbd>Esc</kbd> closes it and returns focus.

### Turning shortcuts off

`keyboardShortcuts={false}` disables the viewer's shortcuts when your app uses the same keys. Toolbar, menu and form keys keep working.

## Customization

Focus indicators are CSS variables: `--rpv-focus-ring` and `--rpv-focus-ring-offset` for toolbar controls, `--rpv-accent` for the document area, thumbnails and links.

## Advanced / escape hatch

To bind different keys, turn the built-in shortcuts off and call the [imperative API](/react-pdf-viewer/imperative-api/) from your own key handler:

```tsx
const viewer = useRef<PdfViewerApi>(null);

useEffect(() => {
  const onKey = (event: KeyboardEvent) => {
    if (event.key === 'j') viewer.current?.nextPage();
    if (event.key === 'k') viewer.current?.previousPage();
  };
  window.addEventListener('keydown', onKey);
  return () => window.removeEventListener('keydown', onKey);
}, []);

<PdfViewer ref={viewer} source={url} keyboardShortcuts={false} />;
```

## Limitations

- **Keys cannot be remapped.** The key map is fixed. Workaround: disable it and handle keys yourself, as above.
- **Shortcuts need focus inside the viewer.** They are scoped to the viewer so they never interfere with the rest of the page. Workaround: focus the viewer programmatically, or use a global handler with the imperative API.
